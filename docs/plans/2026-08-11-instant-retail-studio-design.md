# 即时零售图片工作台设计

日期：2026-08-11

## 背景

现有项目具备成熟的图片生成、参考图、遮罩编辑、历史记录、API 配置、IndexedDB 存储和任务重试能力，但产品模型、提示词、页面结构与导出仍围绕 Amazon Listing/A+。实际业务是美团闪购、淘宝闪购等即时零售平台，需要以单个商品为单位快速产出一套可直接上传的商品图片。

本次改造以“替换 Amazon 工作流”为前提，保留底层生图与存储能力，重建业务策划层、生成队列、质检和导出。

## 已确认目标

- 第一阶段聚焦单商品整套生成，不做批量 Excel、多 SKU 队列或平台直传。
- 每个商品固定产出 7 张：白底主图、商品正面、核心卖点、商品细节、使用场景、规格信息、详情长图。
- 默认面向美团闪购和淘宝闪购，平台规格可切换和维护。
- 商品包装、品牌、规格、颜色、数量和售卖内容必须真实，不允许模型编造。
- 客户上传图片与内部质检完全分离，内部提示不得进入成图。
- 原始商品图永不覆盖，单张失败不影响整套任务。

## 商品池依据

全量扫描来源：`主档资料商品池.xlsx`

- 文件大小：77,706,673 字节
- SHA-256：`8e34e16337907d5464d0229b1343309edf4189b926560581a4a8025ac1a9722f`
- 扫描范围：109,441 条商品、40 个字段，无抽样
- 美团：42 个一级类目、1,659 条完整类目路径
- 淘宝闪购：39 个一级类目、1,862 条完整类目路径
- 京东：46 个一级类目、2,750 条完整类目路径
- 运行知识库：1.6MB 紧凑 JSON，覆盖全部一级类目和完整路径

商品池显示：商品名称覆盖 100%，售卖规格 99.7%，品牌 97.0%，卖点 55.1%，描述仅 21.8%；主图普遍已有 5-7 张，但详情图缺失率约 39.4%。因此工具应优先复用真实主图，重点补齐规格信息、销售属性和详情内容，不能依赖描述字段自动补全事实。

## 类目策略

全部平台一级类目映射到 23 套视觉与资料策略，包括包装食品、饮料乳品、酒水、生鲜、冷藏冷冻、鲜食熟食、个护美妆、家清纸品、母婴、宠物、健康医疗、营养滋补、3C 数码、家居厨具、家装建材、服饰鞋包、文具玩具、图书音像、花卉园艺、成人用品、珠宝钟表眼镜、汽车户外和通用商品。

类目选择后，工具从紧凑知识库读取：

- 类目视觉策略
- 7 个图片位的目标
- 类目必需事实
- 商品池中的高频属性键
- 常见售卖单位和规格类型
- 现有主图、详情图数量基线

结构化事实只能来自用户输入、商品池字段或原包装识别。缺失的酒精度、配料、功效、认证、产地、适用人群、规格和包装数量必须提示补充，不得由模型推测。

## 核心工作流

首页使用六步工作流：

1. 上传商品原图
2. 补充商品资料
3. 选择平台和风格
4. 生成 7 图方案
5. 一键生成并内部质检
6. 按 SKU 打包导出

桌面端采用左侧商品资料、中间 7 图任务板、右侧质检与导出的工作布局。移动端改为分步流程，底部只保留当前步骤的主操作，不再用大面积浮层遮挡表单。

## 商品资料模型

必填字段：

- 商品名称
- 平台类目
- 品牌
- 条码或 SKU
- 售卖规格
- 售卖单位
- 净含量或尺寸
- 包装形态
- 类目要求的关键属性

常用可选字段：

- 口味、香型或颜色
- 材质或配料
- 储存方式
- 保质期
- 包装清单
- 适用人群
- 使用方法
- 已确认卖点

高级字段折叠显示，包括场景方向、禁用元素、特殊合规说明和自定义提示词。

## 七图定义

| 图片位 | 目标 | 默认处理 |
| --- | --- | --- |
| 01 主图 | 快速识别售卖商品 | 白底或平台允许的干净背景，商品完整居中 |
| 02 正面 | 包装与品牌识别 | 真实包装正面，避免改字和变形 |
| 03 卖点 | 解释一个已确认优势 | 程序叠加中文，模型只生成背景或辅助视觉 |
| 04 细节 | 展示内容物、材质或结构 | 使用原图细节或真实参考图 |
| 05 场景 | 帮助用户理解使用方式 | 按类目生成真实场景，不添加未售卖物品 |
| 06 规格 | 展示销售属性 | 只使用结构化事实，程序排版 |
| 07 详情 | 汇总核心信息 | 模块化长图，包含名称、规格、属性、使用与储存信息 |

## 商品保真

默认开启保真模式：

- 原商品图作为锁定主体
- 场景和背景可由 AI 生成
- 中文标题和规格文字由 Canvas 程序叠加
- 包装上的品牌、条码、规格和标签不由模型重新绘制
- 用户可进入遮罩编辑修正主体范围
- 创意活动图允许更强风格化，但不作为默认商品主图

## 平台规格

平台规则以版本化预设维护，避免散落在提示词中。美团闪购当前通用主图规则支持 1:1 的 600×600 或 4:3 的 600×450，单图不超过 5MB，要求主体清晰完整、信息与实物一致，并禁止水印、二维码和其他平台标识。规则来源：<https://rules-center.meituan.com/m/detail/guize/681>。

工具保留平台自定义预设，以适应后台类目差异与规则更新。输出前按目标预设进行缩放、格式转换、压缩和文件大小校验。

## 任务与效率

- “一键生成全部”创建 7 个独立任务
- 默认并发 2，允许暂停与续跑
- 单张失败只重试该图片位
- 生成前一次性校验必填事实
- 任务进度和项目自动保存到 IndexedDB
- 已完成图片可单张重做，不影响其他结果
- 提示词与类目知识按商品项目缓存
- 类目知识库作为静态 JSON 懒加载，不进入主 JS 包

## 内部质检

质检报告只存在于工具界面和导出清单，不写入图片。检查项目包括：

- 图片尺寸、比例、格式与文件大小
- 商品主体完整度和清晰度
- 商品名称、品牌、规格、数量与项目资料是否一致
- 是否包含价格、具体优惠券、满减门槛、评价或排名
- 是否包含二维码、水印、联系方式或其他平台标识
- 是否出现内部提示、待补充或质检文案
- 规格图是否存在缺失事实或模型编造风险

阻断项未通过时禁止标记为“可上传”，但允许导出草稿供人工处理。

## 导出

导出 ZIP 结构：

```text
<SKU>_<商品名称>/
  01_主图.png
  02_商品正面.png
  03_核心卖点.png
  04_商品细节.png
  05_使用场景.png
  06_规格信息.png
  07_详情长图.png
  manifest.json
```

`manifest.json` 保存平台预设、输出尺寸、商品事实、图片位状态和质检结果，供工具恢复和后续批量流程使用。

## 代码结构

保留现有 API、任务、图片缓存和编辑模块。新增：

- `RetailStudio`：即时零售主工作台
- `retailProduct`：商品资料与校验
- `retailKnowledge`：类目知识加载与检索
- `retailPlanner`：7 图策划与提示词
- `generationQueue`：限流并发、暂停、续跑、重试
- `textComposer`：中文和规格的确定性排版
- `retailQuality`：内部质检
- `retailExporter`：平台转换、命名与 ZIP

原 Amazon Planner 和相关知识文档从首页移除；历史数据不删除，旧任务仍可在历史记录中查看。

## 错误处理

- 缺少关键商品事实：阻止规格图和详情图生成，定位缺失字段
- API 配置错误：保留计划与队列，修复设置后继续
- 单任务失败：记录错误并允许只重试失败项
- 页面刷新：恢复未完成项目和任务状态
- 图片不符合平台规格：本地转换后再次质检
- 商品主体或包装疑似变化：标记人工复核，不自动判为可上传

## 测试与验收

- 单元测试覆盖商品字段校验、类目匹配、7 图计划、队列并发、质检和导出命名
- 使用全部平台一级类目和每类代表路径做知识库覆盖测试
- 使用食品、饮料、酒水、生鲜、个护、家清、母婴、医疗、3C、家居等代表商品做端到端测试
- 桌面端和移动端分别验证无重叠、无内容遮挡、任务可恢复
- 构建产物进行代码分包，解决当前主包约 870KB 的警告
- 保持现有 API、图片编辑、历史记录与数据备份测试通过
