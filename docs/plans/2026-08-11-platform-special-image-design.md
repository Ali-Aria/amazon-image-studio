# 平台特殊图设计

日期：2026-08-11

## 背景

即时零售图片工作台当前固定产出 7 张上传图，但商品池还存在独立的“特殊图”字段。特殊图不是普通营销素材，主要承载商品参数、包装背标、尺寸尺码、礼盒包装和平台要求的真实资质材料。新增能力必须提高资料完整度，同时避免把 AI 生成内容误当作真实商品事实或合规证明。

## 商品池结论

全量学习来源为 77,706,673 字节的 `主档资料商品池.xlsx`，覆盖 109,441 条商品、40 个字段。

- 美团特殊图覆盖 23,119 条商品，占 21.12%，共 27,679 张。
- 翱象特殊图覆盖 21,479 条商品，占 19.63%，共 25,810 张。
- 美团特殊图以 `pictureType=5` 为主，其次是包装背标、尺寸尺码、证照、检测报告、能效水效和礼盒包装等类型。
- 乳品、休闲食品、雪糕、饮品、酒类、美容护肤和家电的特殊图覆盖较高，说明特殊图应由类目和字段共同驱动，不能固定给所有商品生成同一种内容。

样本视觉核验后，将平台特殊图归纳为三类：

1. 可由已验证字段确定性生成：商品信息卡、尺寸参数图、尺码参考图。
2. 可基于真实图片处理：包装背标裁切增强、商品与真实礼盒包装组合展示。
3. 必须提供真实原件：资质证书、授权文件、检测报告、医疗器械备案、能效/水效标签和其他合规材料。

## 目标

- 在现有 7 图之后增加第 8 个“平台特殊图”图片位。
- 根据商品类目、字段完整度和真实参考图自动选择最适合的特殊图类型。
- 覆盖现有 23 个类目原型，并允许用户手动改选符合条件的类型。
- 所有上图文字均来自已验证字段，中文由程序确定性排版。
- 真实材料缺失时不生成、不占位、不进入上传包。
- 内部缺口、来源和真实性提示仅显示在工作台，不进入成图。

## 非目标

- 不生成促销券、价格活动或节日营销海报。
- 不用 AI 编造配料、营养、功效、认证、备案、检测、能效、水效、产地或包装文字。
- 不把商品名称推断结果直接当作可上图事实。
- 不在第一版自动联网检索或自动匹配外部证照。

## 推荐方案

采用“规则控事实、模型做画面、程序写文字”的混合方案。

- 规则层决定特殊图类型、所需字段、允许的数据来源和是否具备生成资格。
- 生成层只处理背景、光影和商品场景，不重绘包装文字。
- 合成层通过 Canvas 写入已验证的中文字段，保证文字准确清晰。
- 真实材料只允许裁切、旋转、透视矫正、去噪、清晰化、缩放和格式转换。
- 质检层在导出前再次检查类型、来源、字段和平台规格。

## 特殊图类型

| 类型 | 适用类目 | 最低条件 | 处理方式 |
| --- | --- | --- | --- |
| `product_facts` 商品信息卡 | 食品、饮料、酒、乳品、零食、个护等 | 商品名称、品牌、售卖规格，以及至少 2 个类目有效字段 | 程序排版；商品背景可由 AI 优化 |
| `dimension` 尺寸参数图 | 家电、数码、家居、家装、汽车户外等 | 已验证的尺寸或关键参数 | 程序标注；不推测数值 |
| `size_guide` 尺码参考图 | 服饰、鞋包、母婴穿戴等 | 已验证的尺码映射 | 程序表格排版 |
| `gift_pack` 礼盒包装图 | 巧克力、酒类礼盒、节日礼物等 | 真实商品图和真实礼盒/外包装参考图 | 保真合成；不生成不存在的包装 |
| `back_label` 包装背标图 | 有包装背面资料的预包装商品 | 真实背标图片 | 裁切、矫正和增强，不改写文字 |
| `authentic_document` 真实材料 | 证照、授权、检测、备案、能效、水效等 | 真实原件 | 仅整理和适配，禁止 AI 生成 |

## 类目路由

路由使用现有 23 个类目原型，并结合字段判断：

- 包装食品、饮料乳品、酒水、冷藏冷冻、鲜食熟食、粮油调味、营养滋补：优先商品信息卡；有真实背标时可改选背标图。
- 个护美妆、家清纸品、宠物、成人用品：优先商品信息卡；资质或检测类材料只走真实上传。
- 家用电器、3C 数码、家居厨具、家装建材、汽车户外：字段齐全时优先尺寸参数图，否则商品信息卡。
- 服饰鞋包、母婴穿戴：字段齐全时优先尺码参考图。
- 巧克力、酒类礼盒和节日礼物：存在真实礼盒参考图时优先礼盒包装图。
- 生鲜、花卉园艺、图书音像、文具玩具、珠宝钟表眼镜等：仅在存在足够有效字段或真实材料时启用，不强制生成。

## 事实与来源模型

新增统一字段事实结构：

```ts
type RetailFactSource = 'user' | 'catalog' | 'ocr' | 'derived';

interface RetailFactValue {
  value: string;
  source: RetailFactSource;
  verified: boolean;
}
```

上图资格：

- `user` 和 `catalog` 字段默认可标记为已验证。
- `ocr` 字段必须由用户确认后才能上图。
- `derived` 只用于类目路由、模板建议和内部提示，不能写入图片。
- 空值、泛值、冲突值和未验证值不参与生成。

第一版兼容现有扁平商品模型：已有用户输入视为 `user + verified`，类目知识推导只用于选图，不作为显示字段。后续导入商品池时可保留更完整的来源元数据。

## 选择算法

1. 读取商品类目原型、结构化字段和已上传参考图。
2. 计算每种特殊图的资格、缺失项和优先级。
3. 若用户已手动选择且仍满足条件，保留选择。
4. 否则按类目策略选择最高优先级的可生成类型。
5. 若只有真实材料类型但原件缺失，状态为“需要真实资料”，不创建生成任务。
6. 若无任何类型满足最低条件，状态为“暂不生成”，不进入导出包。

任何情况下都不得为了凑齐第 8 张图而降低真实性门槛。

## 工作台交互

- 中间任务板由 7 张扩展为 8 张，第 8 张标题为“平台特殊图”。
- 卡片显示自动选择的类型、可生成状态和简短原因。
- 用户可在类型菜单中选择其他当前有资格的类型。
- 缺少字段时，侧栏列出具体缺口，并定位到对应商品字段。
- 需要真实材料时提供上传入口；上传后允许预览、替换和清晰化处理。
- 一键生成只提交具备资格的特殊图；不会因特殊图缺失阻断前 7 张。
- 上传图预览不显示内部来源、审核或缺口文案。

## 数据流

```text
商品资料/真实图片
  -> 字段来源归一化
  -> 特殊图策略评估
  -> 用户确认或自动选型
  -> AI 背景处理 / Canvas 排版 / 原件增强
  -> 特殊图质检
  -> 08_特殊图_<类型>.jpg
```

特殊图策略结果随项目持久化，包含：选择类型、资格状态、缺失字段、事实快照、参考图角色和质检结果。项目恢复时重新评估，避免商品资料更新后沿用过期结论。

## 导出

当特殊图通过质检时，ZIP 增加：

```text
08_特殊图_商品信息卡.jpg
```

文件名中的类型按实际结果变化。`manifest.json` 增加特殊图类型、字段来源和真实性策略摘要。若特殊图未生成或被阻断，ZIP 保持原 7 图结构，不输出空文件。

## 错误处理

- 字段不足：标记“暂不生成”，提示缺失项，不生成占位图。
- 真实材料缺失：标记“需要真实资料”，只开放上传入口。
- OCR 未确认：允许预览识别结果，但禁止进入画面和导出。
- 商品与礼盒参考图不一致：阻断礼盒图并要求人工复核。
- 生成失败：只重试第 8 张，不影响前 7 张。
- 商品资料更新：清除过期特殊图的“可上传”状态并重新质检。

## 测试与验收

- 单元测试覆盖六种类型的资格、优先级、缺失项和手动选择回退。
- 安全测试覆盖未验证字段、推断字段和证照类型不可进入生成提示词或成图文案。
- 策划测试确认原 7 图顺序不变，第 8 张只在满足条件时加入任务。
- 导出测试确认特殊图可选、命名准确、无空文件，`manifest.json` 可追溯。
- UI 测试覆盖类型选择、缺口提示、真实资料上传、状态变化和恢复。
- 代表商品覆盖食品饮料、酒类礼盒、家电、服饰和医疗器械五条路径。
- 桌面与移动视口检查无重叠、遮挡和文字溢出。

## 验收标准

1. 有完整食品字段时自动生成商品信息卡。
2. 有真实礼盒参考图时可生成礼盒包装展示，不得添加不存在的包装。
3. 尺寸或尺码字段不足时不生成对应图片。
4. 证照、检测、备案和能效水效材料永远不会触发 AI 生成。
5. 前 7 张生成、质检和导出行为保持兼容。
6. 特殊图通过质检后以第 8 张进入上传包，未通过时自动省略。
