# 即时零售图片工作台

面向美团闪购、淘宝闪购等即时零售业务的商品图片生产工具。输入商品资料和参考图后，工作台按 7 张基础图加 1 张可选平台特殊图完成策划、生成、中文排版、内部质检和 ZIP 导出。

## 核心流程

1. 上传真实商品参考图，商品包装始终作为生成依据。
2. 输入条码从主档带出商品资料，再补齐类目要求的其余客观字段。
3. 选择平台尺寸、视觉风格和并发数。
4. 一键生成 7 张基础图，并按类目与资料条件补充 1 张平台特殊图。
5. 在内部质检区核对尺寸、资料完整性、包装一致性和违规文案风险。
6. 按 SKU 导出命名稳定的图片和 `manifest.json`，或导出可直接喂平台批量通道的上传包。

多个商品可以按条码命名图片一次导入，批量生成后打成一个总包。

## 基础 7 图

| 序号 | 图片位 | 作用 |
| --- | --- | --- |
| 01 | 白底主图 | 完整、居中展示实际售卖商品 |
| 02 | 商品正面 | 强化包装、品牌与规格识别 |
| 03 | 核心卖点 | 展示由已确认商品资料生成的简短卖点 |
| 04 | 细节展示 | 放大包装或产品结构细节 |
| 05 | 使用场景 | 生成符合品类的真实消费场景 |
| 06 | 规格信息 | 用确定性中文排版展示销售属性 |
| 07 | 详情长图 | 汇总商品信息、卖点和使用场景 |

消费者可见图片不会写入“待补充”“内部质检”“资料检查”等内部流程文案。价格、具体优惠券、二维码、水印、联系方式和其他平台标识会被规则拦截或要求人工复核。

## 逐图片位生成配方

七张基础图不是同一条提示词跑七遍。每个图片位有一份配方（`src/lib/retailSlotRecipes.ts`），声明它自己的景别、机位、主体位置、背景、光线、允许模型创造什么、必须原样保留什么，以及这一位专属的负面词；渲染成固定顺序的纯英文标签块，一行一条约束。

- **主体安全区是算出来的，不是写死的**。`computeSlotSafeBox` 从合成层几何常量出发，穿透 `drawCover` / `drawContain` 的裁切与留白数学，给出**生成图坐标系**下的百分比。核心卖点图与规格信息图的文案面板会盖住画布左侧 5.5%–53.5%，所以这两位的商品必须落在右侧，静区右缘由同一份常量推导——两侧永远不会错开。
- **模型只创造光、背景和环境**。包装、品牌、印刷文字、颜色、比例、件数一律从参考图像素级复制；细节图只允许对参考图里已经存在的表面放大，不允许合成看不见的切面或内容物。
- **件数 fail-closed**。“买一送一”“组合装”这类含糊写法一律不猜件数；多件装不会下达把整箱压成单件的负面词。
- **类目只填槽，不写句子**。类目原型提供按图片位键控的方向与受控名词（细节特写允许的表面、印规格的那一面、场景承托面、机位、转角上限），句子骨架永远来自配方表。

## 平台特殊图

第 8 张图片是可选增强项，不会为了凑图而编造资料。系统按商品类目、可信字段和参考图角色自动选择：

- 商品信息卡：食品、饮料、酒类、个护等，文字只来自已确认字段。
- 尺寸参数图：家电、数码、家居等，仅在尺寸、型号或功率字段齐全时生成。
- 尺码参考图：服饰、鞋包和母婴穿戴，仅使用真实尺码映射。
- 礼盒包装图：必须同时提供商品主体和真实礼盒/外包装参考图。
- 包装背标图：只对真实背标原图做裁切、清晰化和规格适配。
- 真实材料图：证照、检测、备案、能效和水效材料只允许使用真实原件。

上传参考图时需要标记为“商品主体”“包装背标”“礼盒/外包装”或“真实证照材料”。非商品资料不会被发送到基础 7 图任务；证照与背标也不会进入 AI 生图链路。

## 商品池知识

工作台的类目引擎来自对本地 `主档资料商品池.xlsx` 的全量结构化扫描，而不是抽样：

- 109,441 条商品记录、40 个字段
- 美团：42 个一级类目、1,659 条完整类目路径
- 淘宝闪购：39 个一级类目、1,862 条完整类目路径
- 京东到家：46 个一级类目、2,750 条完整类目路径
- 归纳为 23 种图片策划原型，一级类目全部有映射

运行时使用精简知识文件 [`public/knowledge/retail-category-knowledge.v2.json`](public/knowledge/retail-category-knowledge.v2.json)，支持完整类目搜索、类目专属资料字段、场景建议和安全回退。原始 77MB 工作簿不打包进前端。

完整扫描脚本、19MB 审计明细和统计摘要保存在本机工作区的 `research/product-pool-2026-08-11/`，前端仓库只携带运行所需的精简知识文件。

## 条码带出与批量商品

在本机生成商品主档索引后，输入或扫入条码即可带出商品名称、品牌、售卖规格、售卖单位、净含量、平台类目和销售属性，并显示该商品在主档里已有多少张主图、详情图和特殊图：

```bash
python3 scripts/build_retail_product_index.py /路径/主档资料商品池.xlsx
```

- 索引按条码末两位分成若干分片写入 `public/knowledge/product-index/`，前端按需只拉取命中的那一片。
- 带出**只填空位**，已经填写过的字段一律保留原值，冲突项会在提示里逐条列出，不会被主档悄悄改写。
- 索引是经营数据，已在 `.gitignore` 中排除，不进仓库也不上传。**未生成索引时条码带出自动关闭**，其余功能不受影响。

批量商品面板接受一批以条码开头命名的图片（`6941876270606.jpg`、`6941876270606_2.jpg`），同一条码的多张图归到一个商品，自动建项目并带出资料，可批量生成并导出总包。

## 平台批量上传包

除了 `01_主图` 这类可读命名，导出还支持按平台批量传图通道要求命名：文件名为 `货号_编号`，编号连续，可选从 `_1`（连主图整套替换）或 `_2`（只补附图）起，包内附批量导入注意事项。

编号跳号会导致整批导入失败，所以被质检拦下的图片位不占编号；货号（店内码）缺失时导出会直接拦截并提示，不会退回用条码当前缀——那样在平台侧一个商品都匹配不上。

## 平台规则

内置美团方图预设采用 600×600px，单图上限 5MB，并在生成和质检阶段要求商品完整、居中、清晰且与实际售卖商品一致。规则依据：[美团闪购商品信息发布管理规范](https://rules-center.meituan.com/m/detail/guize/681)。

淘宝闪购预设标记为可编辑的业务默认值，正式上传前应按当前商家后台提示复核尺寸和文件限制。

## 保留能力

除即时零售工作台外，顶部导航仍保留上游的图片编辑和 AI 人物打标工具。图片生成接口继续支持原项目已有的 OpenAI 兼容接口、火山方舟、阿里云百炼等配置方式。

## 本地运行

```bash
npm ci
npm run dev
```

打开 Vite 输出的本地地址，在“接口设置”中配置可用的图片生成接口、API Key 和模型。

用于本地联调的模拟接口：

```bash
npm run mock:api
```

### 商品图修复与 QNH Bridge

“商品图修复”会先读取 QNH 当前主图、详情图和特殊图，要求逐张保留或剔除，并对每张拟写入图片完成人工 PASS/REJECT 与包装保真核对。审核通过后生成不可变计划，再由本机 Bridge 受控执行；写入是否成功只以 fresh-fetch 后三类图集逐项 exact 一致为准。

先用完全离线的演练模式走通流程：

```bash
npm run qnh:bridge:fake
npm run dev
```

演练 SPU 为 `123456789`。真实模式配置、人工确认要求、固定接口和故障留痕见 [`tools/qnh-bridge/README.md`](tools/qnh-bridge/README.md)。自动测试不会触碰真实 QNH 门店。

## 数据与隐私

- 项目、图片和配置默认保存在浏览器本地 IndexedDB。
- 只有执行需要模型的任务时，对应商品参考图和提示词才会发送到所配置的模型服务。
- 确定性信息卡、尺寸尺码图、背标和真实材料处理在本地完成；证照原件不会发送到生图模型。
- 导出包包含当前商品的 7 张基础图、通过质检的可选特殊图和交付清单；内部质检信息不会合成到消费者图片中。
- 商品主档索引在本机生成并只在浏览器内查询，不随仓库分发，也不会发送到任何服务。
